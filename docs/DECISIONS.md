# Architectural Decisions

| ID | Decision | Rationale |
|---|---|---|
| D-001 | Use SQLite in-memory for unit/integration tests | No Postgres required for CI; registry tests are fully isolated |
| D-002 | Mock backend via respx in tests | No live backend needed; avoids network dependency in tests |
| D-003 | In-process InMemoryDedupStore for quality stage | Sufficient for single-worker pipeline runs; can be replaced with Redis-backed store |
| D-004 | Tor proxy = disabled by default | Setting `TOR_SOCKS_PROXY=` in .env enables it; no real dark-web sources used |
| D-005 | Synthetic test sources only | No real onion/dark-web URLs in source seed; all fixtures are local HTML files |
| D-006 | Celery queue uses Redis as both broker and result backend | Simplest setup; one less service |
| D-007 | SimHash bit width = 64 | Balances collision resistance and speed for content dedup |
| D-008 | Near-duplicate threshold = Hamming distance ≤ 3 | Conservative; tunable via NEAR_DUP_THRESHOLD constant |
| D-009 | Schema version pinned in NormalizedRecord | Downstream consumers can reject incompatible versions |
| D-010 | Parser registry uses Python decorators | Zero-config plugin registration; add a file, decorate a function |
| D-013 | Incremental crawl state persisted on `Source.etag`/`last_modified`/`crawl_cursor` in the registry DB; skips via 304 / content-digest (SHA-256) | Reuses the existing registry (file SQLite) for per-source cursors; no new store needed for incremental state; skips only already-collected permitted content |
| D-014 | File-based `sqlite3` checkpoint store (`data/crawl_checkpoints.db`), separate from the registry, for crash/resume recovery | Stdlib `sqlite3` keeps the resume store independent of SQLAlchemy/registry lifecycle; `run_pipeline_for_source` saves a `running` checkpoint and marks `done`/`failed`; `resume_interrupted_crawls` re-runs interrupted (non-terminal) runs in-process |
| D-011 | Source registration is config-driven via a JSON file (`config/sources.json`, stdlib `json` only — no new dependency); `load_sources_from_config` is idempotent (skips existing URLs) and respects the authorization hard gate — entries with empty/missing `auth_ref` raise `AuthorizationError` and are skipped (counted as skipped, never registered or queued) | Operators add sources without code changes; the loader cannot bypass the auth gate, so an unregistered/no-auth source can never be queued |
| D-012 | Source health is computed from success ratio (`success_count/(success+failure)`), the just-succeeded response time, and last-success age; `_classify_health` returns `recovered` when a source that was `unavailable` (≥3 consecutive failures) succeeds again. Thresholds (`health_slow_response_ms=2000`, `health_stale_success_age_s=86400`, `health_low_success_ratio=0.5`) are config-driven; `evaluate_health` recomputes state from last-success age alone for the scheduler/probe | Health reflects real crawl behavior (success rate + latency + freshness) rather than only the consecutive-failure count; the `recovered` transition was previously unreachable |
| D-015 | Parser format detection via content-type, URL suffix, or content sniff (`detect_format` → `rss`/`atom`/`json`); `parse_rss`/`parse_atom`/`parse_json` register under *format* keys (NOT new `source_type` enum values — the frozen v1.0 `SourceType` set `forum\|paste\|blog\|marketplace\|news\|other` is unchanged); `get_parser_for` prefers a detected format parser and falls back to `get_parser(source_type)` (and its generic fallback); the runner extract step is format-aware | Adds RSS/Atom/JSON sources without touching the frozen schema or the source-type contract; feed parsers use stdlib `xml.etree`/`json` (no `feedparser` dependency); existing type-based tests stay unchanged and still pass |
| D-016 | Baseline benchmark (`scripts/benchmark.py`) runs the REAL in-process pipeline — extract via `get_parser_for` → `normalize` → `QualityChecker.check` — over a synthetic dataset of frozen HTML/feed/JSON fixtures plus generated variants with a known exact/near-duplicate distribution; ingestion is mocked with `respx` (no live network, no real backend). Throughput, per-stage avg latency (extract/normalize/quality/ingest), success rate, and dedup rate are measured with `time.perf_counter` and never fabricated; `tests/unit/test_benchmark.py` smoke-checks the returned keys, and the real stdout is captured to `.agents/tasks/phase2/benchmark_output.txt` for the report | Reproducible, network-free Phase-2 baseline that reflects actual pipeline behavior with no invented numbers; later phases (3/4) benchmark against these measured values |
